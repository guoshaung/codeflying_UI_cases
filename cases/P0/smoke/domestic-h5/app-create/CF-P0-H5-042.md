# CF-P0-H5-042 提示词文案进入文本输入框

- 优先级：P0
- 模块：国内H5 / 应用创建 / 点击提示词气泡
- 平台：国内H5
- 执行方式：可自动化
- 问题类型：产品体验
- 用户类型：免费用户 / 付费用户
- 前置条件：CF-P0-H5-041 已进入需求澄清/创建应用页面；或本用例自行按 041 的步骤进入该页面。
- Agent 分组：h5_workspace_runner
- 账号类型：default-playwright-session
- 是否修改数据：yes
- 数据锁：`app:{app_id}`
- 清理动作：本用例只验证提示词进入输入框，不提交生成；通常无新应用需要清理。
- 人工测试原因：无
- XMind 原始标记：`priority-1`

## 测试步骤

1. 优先复用 CF-P0-H5-041 成功后的当前页面；若单独执行，则先按 CF-P0-H5-041 进入需求澄清/创建应用页面。
2. 定位需求输入框：优先查找 textarea、input、contenteditable、uni-textarea、placeholder 包含“想做什么/描述/需求/应用/请输入”的元素。
3. 若页面存在提示词气泡，点击一个提示词气泡，验证文案进入输入框。
4. 若没有可点击提示词气泡，直接向需求输入框输入一段稳定测试文案，例如：`创建一个简单的待办事项应用`。
5. 如果点击提示词或输入后出现“选择生成类型/你想生成什么类型/网站/小程序/H5/应用”等请求确认卡片，不要把它当失败；记录卡片存在，并验证当前输入/选择流程可继续。
6. 读取输入框 value/textContent/innerText 或相关 Vue/uni-app 绑定值，确认文本已进入输入框。
7. 记录页面状态、URL、关键 DOM、输入框值和截图。

## 预期结果

1. 提示词文案或手动输入文案成功出现在需求输入框中。
2. 页面无白屏、无未处理报错，相关功能可继续操作。
3. 不要求点击提交，不要求等待 AI 回复或应用生成完成。

## 通过标准

- 输入框中能读取到提示词/测试文案，或页面对话/输入区域展示该文案，即可 PASS。
- 如果提示词气泡不存在，但手动输入成功，应判 PASS，并在备注中记录“无提示词气泡，改用手动输入验证输入框能力”。
- 如果输入框是 uni-app 自定义组件，必须尝试 `fill`、`type`、`evaluate` 设置 value + dispatch input/change 事件，不得只因普通 fill 失败就判 FAIL。

## 失败条件

- 已进入需求澄清页面，但找不到任何可输入需求的控件。
- 输入/点击提示词后，无法在输入框、页面文本或绑定值中读取到对应文案。
- 页面出现错误状态或不可继续操作。

## 阻塞条件

- CF-P0-H5-041 无法进入需求澄清/创建应用页面，且本用例单独执行也无法进入。
- 登录态失效、H5 入口不可用、测试环境或必要数据不可用。

## 证据要求

- 输入前后截图。
- 页面 URL、输入框选择器、输入前后 value/textContent。
- 如出现请求确认卡片，记录卡片文案和可用确认按钮。
- 如使用 evaluate/dispatchEvent，记录触发方式。

## 备注

- 本用例只验证“文案进入文本输入框”，不要提交生成，不要等待应用生成完成；生成链路属于其它用例。
