# CF-P0-H5-042 国内H5会员购买拉起支付宝支付

* 优先级：P0
* 模块：国内H5 / 个人中心 / 会员类型 / 充值会员
* 平台：国内H5
* 执行方式：可自动化
* 问题类型：产品体验
* 用户类型：付费用户
* 前置条件：加载对应端的 Playwright session；需要应用时使用稳定、非转圈的测试应用。
* Agent 分组：membership_credit_agent
* 账号类型：default-playwright-session
* 是否修改数据：yes
* 数据锁：`payment:{account_id}`
* 清理动作：不得完成真实支付；不得产生真实扣款
* 人工测试原因：真实支付宝付款完成需人工或支付沙箱专项验证；本用例只验证会员购买流程能够正常拉起支付宝 H5 收银台，不验证最终付款成功。

## 测试步骤

1. 创建独立的国内 H5 Browser Context，使用移动端 viewport，并加载 `default-playwright-session`。

   * 不要求注入微信 UA。
   * 不得为了满足旧用例预期伪造微信内置浏览器环境。

2. 打开真实 H5 入口：
   `https://dev.codeflying.net/codeflying_h5/`

3. 必须先点击底部导航“个人中心”，进入真实个人中心页面。

   * 禁止停留在首页、发现页或其他页面直接全局查找“充值会员”。
   * 应通过用户真实可见路径进入会员购买流程。

4. 确认个人中心页面已经成功渲染。
   可使用以下任一可见特征辅助确认：
   * 用户信息
   * 会员卡片
   * “尊享版”
   * “免费版”
   * “会员类型”
   * “在线客服”
   * “退出登录”

5. 点击“充值会员 / 立即购买 / 购买会员”等实际存在的会员购买入口，进入会员购买页面。
   点击策略：
   * 首选真实用户交互方式 `locator.click()`。
   * 如元素真实可见、可操作，但因前端事件绑定导致普通点击无法触发，可进行一次替代触发。
   * 替代触发最多选择一种，不得循环切换多种点击方式反复尝试。
   * 可选替代方式：
     * `locator.dispatchEvent('click')`
     * `page.evaluate(() => targetElement.click())`
     * `click({ force: true })`
   * 使用替代方式时必须记录原因及结果。
   * 不得因为第一次普通 `.click()` 未跳转就立即判定 FAIL。
   * 同一目标元素最多进行 2 次有效触发尝试。

6. 在会员购买页面选择任一可购买会员套餐，并点击“立即购买”或等价购买按钮。

7. 点击购买后，观察页面行为和导航结果。

   重点检查：

   * 当前页面是否发生 URL 跳转；
   * 是否打开新的页面 / popup；
   * 是否跳转至支付宝 H5 收银台；
   * 是否出现支付宝付款相关 UI；
   * 是否产生支付宝支付相关网络请求。

8. 若页面跳转至支付宝域名，例如：

   `https://mclient.alipay.com/h5pay/...`

   或其他明确属于支付宝官方收银台的页面，则确认支付宝 H5 支付入口已经成功拉起。

9. 到达支付宝收银台后立即停止支付流程。

   * 不点击“确认付款”；
   * 不输入支付密码；
   * 不进行二维码真实付款；
   * 不完成任何可能产生真实扣款的操作。

10. 记录：

* 点击购买前截图；
* 点击购买后截图；
* 跳转前 URL；
* 跳转后 URL；
* 支付页面关键 DOM / 页面标题；
* 相关支付接口结果；
* browser console 中与本次操作相关的异常。

## 预期结果

1. 用户从“个人中心 → 会员购买”能够正常进入会员购买流程。

2. 选择会员套餐并点击购买后，页面能够正常拉起支付宝 H5 支付流程。

3. 满足以下任一明确支付宝支付特征即可认为支付入口已成功拉起：

   * URL 跳转至 `mclient.alipay.com/h5pay/...`；
   * 页面出现支付宝 H5 收银台；
   * 页面出现明确的支付宝支付前置 UI；
   * 出现其他能够唯一确认已经进入支付宝官方支付流程的结果。

4. 页面无白屏、无前端崩溃、无未处理错误。

5. 本用例不要求完成真实付款。

## 通过标准

满足以下条件即可判定 `PASS`：

* 用户能够通过真实页面路径进入会员购买流程；
* 点击购买后成功进入支付宝 H5 支付流程；
* 出现明确的支付宝支付证据，例如：

  * `mclient.alipay.com/h5pay/...`
  * 支付宝 H5 收银台 UI
  * 等价的支付宝官方支付前置页面；
* 页面未发生白屏或阻断性异常。

特别说明：

**出现支付宝 H5 收银台属于本用例预期行为，不得因为没有出现微信支付、`weixin://` 或微信 JSAPI 而判定 FAIL。**

## 失败条件

满足以下任一情况判定 `FAIL`：

* 点击购买后没有任何支付相关响应；
* 点击购买后仍停留在原页面，且没有支付请求、页面变化或新页面产生；
* 支付入口被触发，但跳转至明显错误页面；
* 跳转过程中出现白屏；
* 页面出现阻断购买流程的前端异常；
* 支付接口返回明确业务失败，导致无法进入支付宝收银台；
* 页面声称已经购买/支付成功，但实际未进入合法支付流程。

注意：

* “没有出现微信支付”不是失败条件。
* “没有出现 `weixin://`”不是失败条件。
* “没有微信 JSAPI”不是失败条件。

## 阻塞条件

以下情况判定 `BLOCKED`，不得通过持续重试试图绕过：

* 登录态失效且无法通过当前测试 session 恢复；
* H5 入口整体不可访问；
* 会员购买服务不可用；
* 支付服务整体不可用；
* 支付宝支付通道测试环境不可用；
* 当前账号不存在可购买套餐；
* 必要测试数据不可用；
* 外部支付宝服务本身不可访问。

对于外部支付页面已成功拉起、但因为真实付款需要人工操作的情况：

* 如果已经成功进入支付宝 H5 收银台，则本自动化用例仍可判定 `PASS`；
* 不应因为无法完成最终付款而判定 `BLOCKED` 或 `FAIL`。

## 证据要求

必须记录：

* 进入会员购买前截图；
* 点击购买前截图；
* 支付拉起后的截图；
* 跳转前 URL；
* 跳转后 URL；
* 支付页面 title 或关键 DOM；
* 支付相关接口请求和响应；
* HTTP 状态码；
* 业务接口中的业务码和关键返回字段。

其中：

* HTTP 200 不等于业务成功；
* 必须同时检查接口业务码和响应数据；
* 如 URL 已进入 `mclient.alipay.com/h5pay/...`，应作为支付宝 H5 收银台成功拉起的重要证据。

## 自动化边界

本用例只负责验证：

`个人中心 → 会员购买 → 选择套餐 → 点击购买 → 成功拉起支付宝 H5 收银台`

本用例不负责验证：

* 支付宝账号登录；
* 支付密码；
* 实际资金扣款；
* 支付完成回调；
* 会员到账；
* 支付成功后的订单状态。

上述内容应由独立的支付沙箱用例或人工专项测试覆盖。

## 备注

* 当前实测会员购买流程默认进入支付宝 H5 收银台。
* 已观察到的实际支付页面域名为：
  `mclient.alipay.com`
* 因此本用例不再注入微信 UA，也不再以微信 JSAPI、`weixin://` 或微信支付 UI 作为通过标准。
* 自动化执行到支付宝 H5 收银台后立即停止，不继续执行任何真实付款动作。
