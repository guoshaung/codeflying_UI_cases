# 报告规则

## 日常简报

日常巡检或普通回归测试结束后，输出一份 30 秒能读完的 Markdown 简报：

- 测试时间、环境、端、suite；
- 总共跑了多少条；
- `PASS` / `RETRY_PASS` / `FAIL` / `BLOCKED` / `NOT_RUN` 数量；
- P0 / P1 / P2 失败和阻塞数量；
- 关键失败与阻塞明细；
- 与昨日 / 上周 / 上月对比；没有历史基线时写“暂无历史基线”；
- 结论和下一步建议。

## 上线报告

上线前测试需要输出更完整的 Markdown 报告：

- 版本、环境、端、模型版本；
- 测试范围；
- 结论：可发布 / 有条件发布 / 阻断 / 建议回滚；
- P0 / P1 / P2 分层结果；
- 失败与阻塞明细；
- agent 评估指标与稳定版本差异；如未覆盖，写“未覆盖 / 待外部评估”；
- 业务影响；
- 阻断项 owner 与期限；
- 豁免记录。

任何 P0 用例失败或阻塞时，不应输出“全部通过”或“建议上线”。
